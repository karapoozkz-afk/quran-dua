# Как выпустить «Библию» в Google Play

Код, текст Библии, карточка магазина и политика конфиденциальности готовы. Осталось то, что может сделать только владелец аккаунта. Шаги идут по порядку; рядом с каждым написано, нужен ли компьютер.

## 0. Что вставить в код (5 минут, можно с телефона через github.com)

Все пропуски собраны в одном файле: `androidApp/src/main/kotlin/app/bibliya/android/AppConfig.kt`.

| Что | Где | Пример |
|---|---|---|
| Email для связи | `SUPPORT_EMAIL` | `bible.app.kz@gmail.com` |
| Тот же email в политике | `docs/privacy-policy.md`, две строки `ВСТАВЬТЕ_EMAIL@example.com` | |

Пока email не вставлен, пункт «Написать разработчику» просто скрыт, приложение работает.

Название пакета `app.bibliya` (в `androidApp/build.gradle.kts`, `applicationId`). После первой загрузки в Play его нельзя поменять никогда. Если хотите своё (например, `kz.вашеимя.bible`), меняйте сейчас.

Текст Библии вставлять не нужно: Синодальный перевод и KJV уже внутри приложения.

## 1. Проверить приложение на телефоне (телефон)

1. Откройте https://github.com/karapoozkz-afk/quran-dua/releases/tag/bible-latest
2. Скачайте `androidApp-debug.apk`, установите (телефон попросит разрешить установку из браузера).
3. Пройдитесь: поиск «мне тревожно», тема «Утрата близкого», чтение главы, «Слушать главу», закладка, план, тёмная тема.
4. Снимите 6 скриншотов по списку из `docs/play-listing.md`.

Отладочная версия ставится рядом с будущей магазинной (у неё другой пакет `app.bibliya.debug`).

## 2. Ключ загрузки (компьютер, 10 минут, один раз)

Google Play принимает только файл `.aab`, подписанный вашим ключом загрузки. Debug-ключ Play отклоняет: это одна из вероятных причин, почему не проходил Коран.

На компьютере с Java:

```bash
keytool -genkeypair -v -keystore upload.jks -alias upload -keyalg RSA -keysize 4096 -validity 10000
base64 -w0 upload.jks > upload.jks.base64   # на Mac: base64 -i upload.jks -o upload.jks.base64
```

Сохраните `upload.jks` и пароль в двух местах (облако + флешка). Потерянный ключ загрузки можно сбросить через поддержку Google, но это неделя переписки.

В репозитории: Settings → Secrets and variables → Actions → New repository secret, четыре секрета:

| Имя | Значение |
|---|---|
| `BIBLIYA_KEYSTORE_BASE64` | содержимое `upload.jks.base64` |
| `BIBLIYA_KEYSTORE_PASSWORD` | пароль хранилища |
| `BIBLIYA_KEY_ALIAS` | `upload` |
| `BIBLIYA_KEY_PASSWORD` | пароль ключа (обычно тот же) |

Затем Actions → «Bible app» → Run workflow (ветка `bible`). Через 3–4 минуты в релизе `bible-latest` появится подписанный `androidApp-release.aab`.

**Никогда не кладите `upload.jks` и пароли в сам репозиторий: он публичный.** `.gitignore` уже не пускает туда `*.jks` и `keystore.properties`.

## 3. Play Console (телефон или компьютер)

1. Создать приложение: язык по умолчанию русский, название «Библия: что читать сегодня», тип «Приложение», «Бесплатное».
2. Store presence → Main store listing: вставить тексты из `docs/play-listing.md`, загрузить значок, картинку 1024×500 и скриншоты.
3. App content: заполнить по таблице из `docs/play-listing.md`. Ссылка на политику конфиденциальности:
   `https://github.com/karapoozkz-afk/quran-dua/blob/bible/docs/privacy-policy.md`
4. Release → Testing → Closed testing → создать трек, загрузить `.aab` из релиза `bible-latest`.

## 4. Закрытый тест: 12 человек, 14 дней (без этого не будет продакшена)

Правило Google для личных аккаунтов, созданных после 13 ноября 2023: перед публикацией нужен закрытый тест, в котором **не меньше 12 тестировщиков** участвуют **14 дней подряд**. Только после этого появится кнопка «Подать заявку на доступ к рабочей версии».

- Соберите 12+ Gmail-адресов (родственники, друзья, церковь). Добавьте их в список тестировщиков трека.
- Отправьте им ссылку на участие из консоли. Каждый должен нажать «Стать тестировщиком» и установить приложение из Play.
- Не удаляйте их и не давайте им отписываться 14 дней. Лучше взять 15–20 человек с запасом.
- В заявке на продакшен Google спрашивает, как проходил тест и что исправили. Отвечайте конкретно.

Если аккаунт организационный (на компанию с D-U-N-S), этого шага нет.

## 5. Обновления

Каждая загрузка в Play требует большего `versionCode`. Сборка в GitHub ставит номер запуска сама, поэтому просто запускайте workflow и загружайте новый `.aab`.

Если поменялся текст в `content-src/` или `tools/`, пересоберите контент:

```bash
git clone --depth 1 --filter=blob:none --sparse https://github.com/scrollmapper/bible_databases sm
(cd sm && git sparse-checkout set formats/json && git checkout)
python3 tools/build_content.py --dataset sm/formats/json
```

Если меняется сам текст Библии, увеличьте `CONTENT_VERSION` в `shared/.../db/RoomRepositories.kt`, чтобы телефоны перезагрузили текст.
