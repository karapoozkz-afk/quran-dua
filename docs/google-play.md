# Публикация в Google Play: что сделано и что осталось

Этот файл ведёт от готового кода до приложения в Google Play. Шаги по порядку.

## 0. Что уже готово в коде

- targetSdk 36 (Android 16): с 31 августа 2026 Google Play принимает новые приложения только с ним.
- Release-сборка с R8 собирается в CI, подписывается ключом загрузки из секретов, и CI запускает её на эмуляторе (ловит крэши, которые появляются только после минификации).
- Файл для Play (`.aab`) появляется в артефактах сборки `quran-dua-play-bundle`, когда заданы секреты (шаг 2).
- «Поддержать проект» через Google Play Billing 8: три разовых платежа `support_small`, `support_medium`, `support_large`. Пока товары не созданы в Console, кнопок нет, а приложение пишет, что поддержка доступна в версии из Google Play.
- Раздел фондов скрыт, пока в `content-src/charities.json` нет проверенных фондов.
- Политика конфиденциальности: `docs/privacy-policy.md`.

## 1. Аккаунт разработчика

1. play.google.com/console → регистрация, взнос 25 $.
2. Тип аккаунта. **Личный аккаунт** (на физлицо) требует закрытого тестирования: не меньше 12 тестировщиков, которые не выходят из теста 14 дней подряд, и только потом можно подать заявку на продакшен. **Аккаунт организации** (на ИП) этого не требует, но нужен номер D-U-N-S (бесплатно, обычно 1–4 недели) и подтверждение организации.
3. Платёжный профиль (Merchant): нужен для «Поддержать проект». Казахстан поддерживается. Укажите реквизиты ИП и счёт для выплат.

## 2. Ключ загрузки и секреты GitHub

Ключ загрузки уже создан и лежит в файлах проекта: `quran-app/signing/` (upload.jks, upload.jks.base64.txt, passwords.txt). **Сделайте копию этой папки в надёжное место** (например, зашифрованный архив в облаке). Ключ можно сбросить через поддержку Google, если потеряете, но это занимает дни.

GitHub → репозиторий → Settings → Secrets and variables → Actions → New repository secret, четыре секрета:

| Имя | Значение |
|---|---|
| `RELEASE_KEYSTORE_BASE64` | всё содержимое `upload.jks.base64.txt` |
| `RELEASE_KEYSTORE_PASSWORD` | из `passwords.txt` |
| `RELEASE_KEY_ALIAS` | `upload` |
| `RELEASE_KEY_PASSWORD` | из `passwords.txt` |

После этого любая сборка на GitHub выдаёт подписанный `.aab`. При первой загрузке в Console оставьте включённым **Play App Signing** (Google хранит ключ подписи, у вас только ключ загрузки).

## 3. Создать приложение в Console

- Название по умолчанию: «Коран и Дуа», язык по умолчанию: русский.
- Тип: приложение, бесплатное.
- Package name задаётся первым загруженным `.aab`: `app.qurandua` (изменить потом нельзя).

## 4. Разделы «Контент приложения» (App content)

**Политика конфиденциальности.** Нужен публичный адрес. Самый простой: в GitHub включить Pages (Settings → Pages → Branch `main`, папка `/docs`), адрес будет `https://karapoozkz-afk.github.io/quran-dua/privacy-policy`. Перед этим впишите в файл ФИО/ИП и email.

**Реклама:** нет рекламы.

**Доступ к приложению:** все функции доступны без входа.

**Целевая аудитория:** 13+ (не выбирайте детские возрасты: тогда действуют правила программы «Для детей и семей»).

**Рейтинг контента (анкета IARC):** категория «Справочник/образование», насилия и азартных игр нет; есть покупки внутри приложения. Из-за общей стены отвечайте «да» на вопрос, могут ли пользователи делиться контентом, и укажите, что записи проходят модерацию до публикации. Рейтинг может подняться с 3+ до 12+/Teen; это нормально.

**Пользовательский контент (политика UGC).** Для стены Google требует: правила, которые пользователь принимает до публикации, модерацию, кнопку жалобы и возможность заблокировать злоупотребления. В PR #1 это уже есть: правила над полем записи («пишите без имён…»), проверка каждой записи до публикации и кнопка жалобы.

**Безопасность данных (Data safety)** — ответы, совпадающие с кодом:
- Собирает ли приложение данные: **Да**.
- Местоположение → Приблизительное: собирается, не передаётся третьим лицам, обрабатывается временно (ephemeral), необязательно (можно выбрать город), цель: функциональность приложения.
- Общая стена покаяния (после слияния PR #1): «Сообщения → Другой пользовательский контент»: собирается, не передаётся, обязательно для публикации, цель: функциональность приложения. «Идентификаторы устройства или другие ID»: собирается (анонимный ID Firebase), не передаётся, цель: функциональность приложения и защита от злоупотреблений.
- Данные шифруются при передаче: да (HTTPS).
- Можно ли запросить удаление: да, по email из политики (записи на стене); остальное удаляется вместе с приложением.
- Покупки обрабатывает Google Play Billing; Google сам раскрывает эти данные, отдельно их указывать не нужно (если Console попросит, отметьте «История покупок: собирается, цель — функциональность приложения»).

**Разрешения, которые потребуют объяснения:**
- *Полноэкранные уведомления (USE_FULL_SCREEN_INTENT):* «Окно азана открывается поверх экрана блокировки в момент намаза, как будильник».
- *Точные будильники (SCHEDULE_EXACT_ALARM):* «Напоминания о намазе и азан должны прозвучать в точную минуту».
- *Foreground service:* mediaPlayback — «азан играет при выключенном экране»; dataSync — «скачивание чтения Корана для прослушивания без интернета». Console попросит короткое видео: запишите экран телефона (5–20 с), где запускается азан и где идёт скачивание суры.

## 5. Товары «Поддержать проект»

Console → Монетизация → Товары → Встроенные товары → Создать, три штуки (ID должны совпасть точно):

| ID | Название | Цена (пример) |
|---|---|---|
| `support_small` | Поддержать проект | 500 ₸ |
| `support_medium` | Поддержать проект | 2 000 ₸ |
| `support_large` | Поддержать проект | 5 000 ₸ |

Цены задаёте вы; Play пересчитает для других стран. Товары становятся видны в приложении после того, как оно загружено хотя бы в один трек тестирования.

## 6. Графика

- Значок 512×512 PNG.
- Обложка (feature graphic) 1024×500.
- От 2 до 8 скриншотов телефона: главная → «что прочитать» → дуа с источником → Коран с переводом → время намаза → окно азана.

Всё это лучше делать после выбора дизайна (А/Б/В/Г), иначе придётся переделывать.

## 8. Выпуск

1. Внутреннее тестирование: загрузить `.aab`, добавить себя, проверить на Samsung покупку (тестовые карты Play) и азан.
2. Закрытое тестирование: 12+ человек на 14 дней (для личного аккаунта обязательно).
3. Заявка на продакшен. Проверка Google обычно занимает от нескольких дней до недели.

Каждая новая версия: CI сам увеличивает versionCode (номер запуска сборки), версия для людей задаётся в `androidApp/build.gradle.kts` (`versionName`).
